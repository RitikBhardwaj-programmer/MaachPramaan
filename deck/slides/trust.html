Built so anyone can check it

Seed committed first

Its hash is published before selection and the seed revealed after, so no one can pick a convenient sample

Permanent random numbers

Each pond’s number comes from the seed and its ID, so list order changes nothing and panels rotate cleanly

Hash-chained audit log

Every load, selection, upload, review and estimate run is logged; tampering breaks the chain

Flag, never overwrite

Duplicates, gaps and ×10 slips go to a review queue; the farmer’s original value is always kept

Auditability is designed in. With the frozen pond list, the revealed seed and the code version, an auditor gets byte-identical output: we tested that two runs give identical files. The data-quality checks caught all planted duplicates, gaps and seed inconsistencies, and 73% of ×10 slips, in simulation. One check, diary versus weighed, raises more false alarms than its limit allows; that is reported.
